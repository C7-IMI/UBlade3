# UBlade3 core notes - exact source reference for the first playable port

Scope: fixed timestep/game loop, arena state and collision ellipsoid, camera, player input and
steering physics, rok physics, goal/multiplier rules, and data units. This is the implementation
specification for the C# port: every constant and formula below is quoted from the byte-matching
decompilation with file, function and line, or from a DATA file in an owned retail install. Do not
invent values and do not substitute the modernised 20XX values where they differ; deviations are
called out explicitly.

Sources and citation legend

- Decompilation: third_party/hyperblade-decomp/src, a byte-matching decompilation of HYPERX.EXE
  v1.0.0.1. Citations use path:line and the original address where the decompilation records a
  FUNCTION marker. addresses are canonical lower-case 0x + eight hex digits.
- Symbols: third_party/hyperblade-decomp/symbols/functions.csv (address, name, size, convention,
  signature). Game code is below 0x004a0000; the C runtime and linked libraries are above it
  (third_party/hyperblade-decomp/README.md).
- DATA: DATA folder of an owned retail HyperBlade install (read-only during analysis; never
  committed). Files are cited by basename only.
- Plans: DATA/PLANS/*.PBN are ADLIB compiled AI plans (original game data). Plan excerpts below
  were produced with third_party/hyperblade-decomp/tools/plan_dump.py and are evidence for rules
  that live in plan data rather than in C++.
- 20XX: third_party/hyperblade-20XX is the modernised C++ reference. It is an oracle, not the
  specification; any divergence is labelled referenceOnly.
- Ledger: docs/PORT-LEDGER.json and docs/PORT-LEDGER.md are generated by
  tools/port/generate_ledger.py. A C# file claims a decompilation function by citing its address
  (0x + eight hex digits) or its fully qualified symbol, for example:

  The tool counts TODO, NotImplementedException and NotSupportedException within 40 lines of a
  citation as a stub rather than ported code.

1. Units, coordinate system and time

World space is unitless "data units". There is no metric conversion of world space anywhere in
the decompilation. The arena collision ellipsoid is 105 x 187.5 x 105 data units (see section 3),
dromers spawn at positions such as 40 75 0 (DATA/LOSAN.HTM:4), goals sit at y = +/-192.5
(DATA/HOUDRO.ENV:15), and a goal side bubble has radius 185 (DATA/HOUDRO.ENV:19). Do not rescale
any of this.

Time is milliseconds for clock and timeout values and seconds for the engine delta. TickClock
reads timeGetTime() in milliseconds, subtracts the previous tick, and stores the scaled value in
seconds (engine/gameengine.cpp:609-623). EngineClock fields are at engine/engineclock.h:28-43.

Angles: DATA and object parameters use degrees; physics uses radians. PhysicsBody::BindToObject
converts the definition azimuth with DEGREES_TO_RADIANS = 0.0174532925 (physics/physicsbody.cpp:108,
138-145). The camera uses g_flDegToRadCamera = 0.0174532923847436905 (globals.cpp:537). A negative
azimuth has 360 added first (physics/physicsbody.cpp:138-141). g_flDegreesPerTurn = 360.0f
(globals.cpp:533).

Velocity and displacement: DATA SetMotionParams speed is data units per second. The physics body
stores per-frame displacement: BindToObject sets flForwardSpeedDt = flDelta * m_flSpeed and
flAccelDt = flDeltaSquared * m_flAccel (physics/physicsbody.cpp:131-132); ResetDynamics repeats
it (physics/physicsbody.cpp:180-181); PreUpdateTick repeats it every frame
(physics/physicsbody.cpp:196-198). The code converts a per-frame flSpeed back to per-second by multiplying by
flInvDelta, for example planvm/cglideonsurface.cpp:271 and physics/collisioncheck.cpp:353. DATA
speed 48 (DATA/LOSAN.HTM:4) therefore means 48 units per second, or 2.667 per frame at the
nominal 18 Hz.

Acceleration: DATA accel is data units per second squared, applied as flDeltaSquared * accel at
the body level. g_flGravity = 32.0f (globals.cpp:795) and g_flGravityGameEngine = 32.0f
(globals.cpp:225) are in the same physical units; the delta-squared integration
(flGravDeltaVel = flDeltaSquared * flGravAccel, physics/physicsbody.cpp:194) is the exact
original arithmetic, not an approximation to change.

Ratings: HTM ratings are written as whole numbers but stored as floats; the loader scans them as
numbers and stores floats (globals.cpp:768-769 g_pszPercentD = "%d"; engine/gameengine.cpp:2442
Cmd_SetRatings). ObjectStats::GetWeightedStat scales the current energy into the rating:
    flEnergy = m_aStats[0] * g_flStatWeightScale + 0.25f
    result   = flEnergy * m_aStats[index + 1]
with g_flStatWeightScale = 0.0075f (common/staticinitglobals.cpp:13), energy = m_aStats[0] and
stat 0 = energy = 100.0f at defaults (engine/objectstats.cpp:26-55).

The only centimetre arithmetic in the decompilation is the software renderer projection
(72 dots per inch, 0.75 dot pitch, 2.54 cm per inch; common/staticinitglobals.cpp:19-24 and
engine/cameraprojectionstate.cpp:58-66). It sizes a virtual screen, not the world.

2. Fixed timestep and game loop

The original has no fixed timestep. It advances by the measured frame time, smoothed over five
frames, with 18 Hz as the initial and nominal reference. Any C# implementation claiming exactness
must reproduce GameEngine::TickClock (0x00481130). Pinning a fixed 30 Hz tick is the 20XX
modernisation (third_party/hyperblade-20XX/src/engine/framepacing.h:14 kTickMs = 1000.0f/30.0f;
third_party/hyperblade-20XX/src/engine/gameengine.cpp:565) and must be recorded as a deviation if
used.

Constants (engine/gameengine.cpp:573-583, 1150-1152; globals.cpp:225,519-541,795;
common/staticinitglobals.cpp:33; ui/screens/tournamentsetupuiscreen.cpp:22):

    MATCH_FRAME_RATE      18.0f          nominal frames per second
    MATCH_RATE_SQUARED    324.0f         18 squared
    MATCH_STEP            1.0f / 18.0f   initial flDelta, seconds
    CLOCK_RING_LENGTH     5              engine/engineclock.h:8
    MAX_FRAME_TIME_MS     200.0f         a longer frame is dropped before the delta update
    MS_TO_SEC             0.001f         milliseconds to seconds
    g_flFifthGameEngine   0.2f           one fifth, ui/screens/tournamentsetupuiscreen.cpp:22
    g_flOneGameEngine     1.0f           common/staticinitglobals.cpp:33
    g_flGravityGameEngine 32.0f          data units per second squared
    g_flGravity           32.0f          data units per second squared
    g_flGravityHalf       0.5f           globals.cpp:521

Tick formula (engine/gameengine.cpp:593-633, exact order):

    nPrevTickMs = nTickMs
    nTickMs = timeGetTime()
    g_flFrameDelta = (float)nTickMs - nPrevTickMs
    if (g_flFrameDelta > 200.0f) return
    if (g_flFrameDelta < 0.0f) return
    g_flFrameDelta = 0.2f * g_flFrameDelta * 0.001f
    nSlot = nRingIndex
    flDelta        = flDelta - aflDeltaRing[nSlot] + g_flFrameDelta
    flDeltaSquared = flDelta * flDelta
    flInvDelta        = 1.0f / flDelta
    flInvDeltaSquared = flInvDelta * flInvDelta
    aflDeltaRing[nSlot] = g_flFrameDelta
    nRingIndex = (nRingIndex + 1) % 5

Because the ring starts full of g_flFifthGameEngine * flDelta (engine/gameengine.cpp:1176-1179),
flDelta is the mean of the last five frame deltas in seconds and flInvDelta is the smoothed frame
rate. InitMatchTimers sets flPrevInvDelta = flInvDelta = 18.0f, flDelta = flPrevDelta = 1/18 s,
flDeltaSquared = 324.0f and every ring slot to 0.2f * 1/18 s, so the initial mean is exactly 1/18 s
(engine/gameengine.cpp:1156-1188). nPeriod starts at 1 and nPauseMark at -1.

Frame order (engine/game.cpp:51-114, 0x0044c1b0, and engine/gameengine.cpp:4382-4457,
0x00486b20):

1. Game::RunFrame records the start time, Renderer::BeginScene, calls
   g_pGameEngine->PerFrameUpdate(), then Renderer::EndScene, scene draw, HUD draw and
   Renderer::PresentFrame.
2. PerFrameUpdate clears ENGINEOBJECT_POSED on every object and switches on m_wRunState.
3. ENGINE_RUN_PLAYING: TickClock(); m_flGravityDt = 32.0f * flDeltaSquared; for each object, in
   m_ppObjects order, PhysicsBody::PerFrameTick(); Postpass() when a network session is active;
   BroadcastCollisionEvents(); ProcessInputCommandQueue(); ClearPendingEvents(); then the
   optional session pump and sync.
4. ENGINE_RUN_PAUSED: only GetCamera(CAMERA_MAIN_SLOT)->ViewIt() runs.
5. ENGINE_RUN_RESTART: GameEngine::RestartMatch(), GameEngine::TogglePause(hWnd, 1), return.

Per-object tick (physics/physicsbody.cpp:185-236, 0x00407960/0x004079f0):

    PreUpdateTick:
        flStep = flDelta * flPrevInvDelta
        flSpeed = flStep * flSpeed
        vel.ScaleInPlace(flStep)
        flForwardAccel = flDeltaSquared * flPrevInvDeltaSquared * flForwardAccel
        flGravDeltaVel = flDeltaSquared * flGravAccel
        flForwardSpeedDt = flDelta * flBaseForwardSpeed
        flAccelDt = flDeltaSquared * flAccel
    then, per phase:
        OBJECT_PHASE_LOCAL or OBJECT_PHASE_BUILDING: pTarget->Process(0)
        OBJECT_PHASE_NETWORK: pOwner->ProcessReceivedPacket(); pTarget->Release(0)
    then PlanState->PostUpdateCleanup() and, for KIND_DROMER,
    ObjectStats::UpdateMomentumAndEnergy()

Clock pause semantics (engine/gameengine.cpp:4331-4377, GameEngine::BroadcastEvent
0x00486a10): MSG_SHOOT sets nPauseMark to 1 and records nPauseStartMs, shifting nPeriodStartMs by
the pause; MSG_GOAL_SCORED resets the event base and clears nPauseMark; MSG_START_DRAG resets the
event base, nPeriodStartMs and nPauseStartMs and clears nPauseMark.

(physics/collisionellipsoid.h:66-72). The constructor (0x0042e9b0,
physics/collisionellipsoid.cpp:42-53) sets:

    m_flInvYY = 1.0f / (flY * flY)

For the arena this is invXX = invZZ = 1/11025 = 0.000090702948 and invYY = 1/35156.25 =
0.000028444444.

Ellipsoid queries (physics/collisionellipsoid.cpp; the implementations are the spec):

- PointInside, 0x00408ea0, lines 16-25:
      flSum = invZZ*z*z + invYY*y*y + invXX*x*x; return flSum <= 1.0
- PointNearSurface, 0x00408ee0, lines 28-38:
      same flSum; return flSum <= 0.99f
- GetZ, 0x0042f0d0, lines 346-356:
      remainder = (1.0f - x*invXX*x) - y*invYY*y
      if (remainder < 0.0f) return 1.0f
      return -(sqrt(remainder) * m_flRadiusZ)
  Note the negative root: GetZ gives the lower-half z of the ellipsoid, which is the floor.
- NormalAtPoint, 0x0042f120, lines 362-443: epsilon band AXIS_BAND = 0.0001. It selects the axis
  the point is outside the band on, z first, then x, then y; returns a pointer to m_vNormal
  (not re-entrant) and returns 0 only at the centre. The caller must not keep the pointer after
  the next call.
- ComputeRadialBoundaryXY, 0x0042f040, lines 307-341:
      if |x| > 1e-5: square = x*x; else square = 1e-5, offAxis = false
      radius = sqrt(square / (square*invXX + invYY*y*y))
      if (x <= 0.0f) radius = -radius
      out.x = radius
      out.y = offAxis ? (y/x) * radius : 0.0f
      out.z = z
  The comment records the original bug near the y axis (line 305).
- IntersectRay, 0x0042eb00, lines 97-299: solved in double, parameterised by the first direction
  component outside +/-0.0001 (AXIS_EPS_UPPER/LOWER), quadratic root
      flRoot = halfB*halfB - ((invZZ*armB*armB + invYY*armA*armA) - 1.0) / quad
  with the three axis cases written out separately. The near and far points are ordered with
  Vec3::FindClosest(pOrigin, pNearOut, pFarOut).
- RadiusForDirection, 0x0042f350, lines 450-462:
      horizontal = (|x| + |z|) / 2.0f
      absY = |y|
      total = absY + horizontal
      if (total < 1e-8) return 0
      return (horizontal*radiusX + absY*radiusY) / (3.0f * total)
  The comment says the third semi-axis is never read and the /3 is a tuning constant (line 448).

9. Exactness hazards for the C# port

- Do not replace the measured TickClock with a fixed step unless the Lead records the deviation.
  The nominal 18 Hz is an initial condition, not a fixed tick.
- The 200 ms clamp returns before folding the delta into the ring, but nTickMs and g_flFrameDelta
  are already updated. Reproduce that side effect.
- flDelta is the mean of five frames, not the current frame; flInvDelta = 1/flDelta. Ratios such
  as flDelta * flPrevInvDelta in PreUpdateTick and flDelta * flPrevInvDeltaSquared on
  flForwardAccel must use the previous values.
- PhysicsBody::flSpeed, flForwardSpeedDt and flAccelDt are per-frame; multiply by flInvDelta to
  get units per second. The decompilation does this in comparisons such as
  invDelta * flSpeed > 5.0f (planvm/csteertotarget.cpp:131) and
  invDelta * flSpeed < g_flBankFreeSpeed (planvm/cglideonsurface.cpp:271).
- CollisionEllipsoid::NormalAtPoint returns a pointer into the object; copy it before calling
  again. It returns null only at the exact centre. The axis band is 0.0001.
- GetZ returns the negative root (floor). The YMinus marker passes +6.0f to GetZ even though its
  y is -6.0f; that is the original's behaviour (engine/game.cpp:268-271).
- PointNearSurface is a strict 0.99 test; PointInside is a 1.0 test. They are not the same gate.
- IntersectRay solves in double and parameterises by the first safe direction component, not the
  largest. Do not normalise away that choice.
- The glide integrator uses both the fourth-order velocity history (BodyRing) and the four-entry
  smooth ring; index advance and ring seeding matter.
- Collision response uses both the body's friction/elasticity and the shell's:
  blend = (1 - bodyFriction) - shellFriction; weight = shellElasticity * bodyElasticity.
- The plan VM drives goals, multipliers, input mapping and AI. The engine supplies the actions
  and decision functions (PlanAction::IncRokValue, PlanAction::IncrementScore,
  PlanCond::RokScoreValue, PlanCond::CheckScoreOnOwnGoal, ...), but the rules live in the PBN
  files. Port the plan VM semantics from the decompilation (planvm/) and test against the
  dump; do not hard-code the goal plans into C# without a note.
- DATA/DFTSTICK.CFG's @v02 record leaves the four track offsets zero because of the reader
  misalignment described in section 4. If the C# port parses the same file with a stricter parser
  it will produce different camera offsets than the original; the shipped behaviour is the zero
  offsets, and any different parse must be documented as a deviation.
- The camera poses the eye from posOut + dir x normal * settings.x + dirOut * settings.y +
  surfNormal * settings.z; note the cross-product order and which value scales each term.
- PhysicsBody::SetFlatOnTerrain, ResetOnSurface and UpdateBanking change the local transform and
  camera position as side effects; keep their call order because the next frame reads them.

10. Verification checklist for a ported subsystem

- Unit tests assert the exact constants and formulas in config/core-constants.json against the
  C# implementation, and cite the decompilation address in each test.
- For each ported function, put the 0x address on the C# type or test and rerun
  python tools/port/generate_ledger.py. A function is ledger-mapped only by a citation; parity is
  a separate claim.
- Parity checks against DATA: parse DATA/HOUDRO.ENV, DATA/LOSAN.HTM, DATA/BOOIE.INI and
  DATA/DFTSTICK.CFG, then compare the resulting arena, stats, options and control values with the
  numbers in this document.
- Parity checks against the decompilation: run the 20XX reference build where it is a valid
  oracle (data parsing, match stats) and record it in docs/PORT-LEDGER.md. Never copy its
  fixed 30 Hz clock, controller scaling or other modernisations into the exact core without a
  recorded deviation.
- Plan checks: use third_party/hyperblade-decomp/tools/plan_dump.py to dump INPUT.PBN, NGOAL.PBN,
  SGOAL.PBN, INSCRTBL.PBN and MULTPLR.PBN, and assert the message sequences listed in this
  document against the port's plan dispatcher.
